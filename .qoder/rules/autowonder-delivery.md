# AutoWonder Delivery Conventions

> Distributed by `qoder-terminal-web/scripts/sync-rules.sh`. **Do not edit this file inside individual repos.**

This project consists of four repos delivered in AutoWonder by a digital worker pipeline: **Full-Stack Developer → Code Reviewer → QA & Deployment Engineer → human acceptance**.

| Repo | Language | Contracts owned |
|---|---|---|
| `qoder-terminal-data` | Go | `api/openapi.yaml` |
| `qoder-terminal-analyst` | Python | `api/openapi.yaml`, `api/agent-event.schema.json` |
| `qoder-terminal-user` | Java | `api/openapi.yaml`, JWT claims, Flyway migration scripts |
| `qoder-terminal-web` | TypeScript | Consumer; contains `e2e/` |

## Standard entry points
| Command | Purpose | Main users |
|---|---|---|
| `make test` | Unit tests | DEV (baseline before changes, regression after) |
| `make lint` | Formatting, static checks, type checks, OpenAPI lint | DEV; CR checks the evidence |
| `GET /health` | Post-deployment health check (data :8081, analyst :8082, user :8084) | QA |
| user `make db-migrate` | Run Flyway migrations (services never migrate on startup) | QA database steps |
| web `make e2e` | Post-deployment cross-repo verification | QA |

## Development (DEV)
1. Run `make test` before starting to record the **legacy-behavior baseline**; report baseline failures first and never change code before capturing the baseline.
2. TDD: write a failing test, implement, then refactor.
3. **Contract first**: cross-repo requirements merge the provider repo's contract change first; consumers never invent fields.
4. `make lint test` must fully pass before committing; zero tests, skips, or unexecuted runs do not count as passing.

## Review (CR)
- Read-only review: no builds, no code changes; defects are REJECTed back to DEV with file and line references.
- Focus: contract consistency, no floating-point price math, error handling, no committed credentials, no real network access in tests.

## Evidence
- Real command output and conclusions of every step go to `evidence/` (sealed and uploaded by the AutoWonder Runtime).
- Never fabricate evidence; test results on mock data cannot pass off as post-deployment tests.

## Database changes (qoder-terminal-user only)
- PostgreSQL with the `qoder_user` schema; changes are made only by adding Flyway scripts, never by modifying merged scripts.
- Automatic migration on startup is disabled; migrations run only in the QA database step via `make db-migrate`, after a backup.
- data / analyst / web have no database: the database steps of their work items are marked "not applicable" with justification in the evidence.
